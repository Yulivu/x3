# X3 · NEW_TASKS 10（冲刺 1：6–9 小时，往"对等基线下的 SOTA + 方法卡"推进；只在这台 HPC 上算；GPU / CPU 不空转）

## 0. 对 09 的补丁（先读）
1. **P1 的说话人不相交细则**：目标平台为 p 时，源 = 其余平台中、**其说话人在 p 上没有任何 clip** 的全部标注 clip（7 个多平台说话人因此会从源里剔除）。P1 只用 **v3 dev**。目标平台评测集里真、假各 <30 条（扣掉库之后）的平台不进宏平均，单列报告。
2. **P3（冻结后一次）**：源 = v3 dev 全部；目标平台 p = v3 test 中平台为 p 的 clip；库 = 同平台 test 里其它说话人的真样本；指标同 P1。
3. **PCA / 标准化只用源平台拟合**（归纳式）。超参只在源内用"留一平台 CV"选。目标标签只用于评测，以及构造污染与"神谕诊断"（必须标注 `ORACLE_DIAG`，不进主表）。
4. **BASE_M 补一个最强堆叠 `stack-5`**：LR 融合 `[B1 logit, Z0, c1, c3, cc, E-norm-s 距离]`，融合权重由源内留一平台 CV 选。G40 的"最强对手"在 `stack-5` 与其它对手里取最强者。
5. **M-A 的头部变体**：主版本 LR；另报 LightGBM（浅树）与 2 层 MLP 两种头（同特征、同调参预算）。选择规则按 09（复杂方法要多赢 ≥0.5）。
6. 单测（失败即停该包并报告）：(a) OC 分数方向：距离越大越假，`EER(−s) = 100 − EER(s)`；(b) 库屏蔽：任何 query 的距离矩阵里不含其说话人的库成员；(c) 库 clip 不在评测集里；(d) LOPO 切分：源与目标说话人集合不相交；(e) E-norm-s 的尺度不变性（09 已有）；(f) 冲刺内任何包读到 test 的 clip 即报错。

## 1. 硬约束与机器配额（vGPU-32GB × 1，16 vCPU，80 GB 内存，系统盘 30 GB，数据盘合计 280 GB、当前空闲约 70 GB）
- **只在这台机器上计算。** 不要把任何计算搬到别处；终局产物只打一个结果包（§6）供备份与写作。
- **线程与优先级**（`OMP_NUM_THREADS=MKL_NUM_THREADS=OPENBLAS_NUM_THREADS` 按下列设）：A 车道 5 线程；B 车道 3 线程且 `nice -n 10`；G 车道数据加载 `num_workers=4`；ffmpeg 并发 ≤3（只在转码阶段，那时暂停 B 车道）；永远留 ≥2 个 vCPU 给系统和 agent。优先级 G 的数据加载 > A > B。5 分钟平均负载 >14 持续 10 分钟 → 先暂停 B（存断点），被暂停的包顺延，不算 `TIMEOUT`。
- **重活放 GPU，减轻 CPU**：harness 用 PyTorch 写成设备无关（批量余弦距离、排序求 EER、批量说话人聚类自助法），在 GPU 上跑；逻辑回归用 torch 的 LBFGS；梯度提升头优先 XGBoost `device="cuda"`，没有就 LightGBM `n_jobs=3` 并把树数减半。CPU 只做调度、读写与小表汇总。
- **音频只解码一次**：把 v3 dev（及按需的其它子集）一次性解码成 int16 memmap（约 3.3 GB），所有 GPU 包共用，避免重复解码吃 CPU。
- **内存**：每条 CPU 车道 ≤20 GB；GPU 同时驻留 ≤24 GB。**GPU 车道允许 2 个并发包**（总显存 ≤24 GB，且至多 1 个"重"包——重提特征 / 声码器）；网络下载是独立后台，不占名额。
- **磁盘**：先 `df -h` 写入 `preflight.md`。所有缓存放数据盘（`HF_HOME`、`TORCH_HOME`、`PIP_CACHE_DIR`、`TMPDIR`、conda 环境），系统盘只放代码。本冲刺新增占用峰值约 31 GB（空闲 70 GB 足够）：ITW ≤17 GB（zip 8.2 GB + 解压，解压后立刻删 zip）、音频 memmap 与转码 memmap 各 ≈3.3 GB（只存 dev）、反事实面板的重合成 / 扰动音频 ≈3 GB、非后训练逐层特征 ≈1.2–2.4 GB（fp16）、帧级特征 ≤1.3 GB（第二梯队才用）、检查点与结果 ≤5 GB；FSW 子集（仅 ITW 不可得时）另加 ≤10 GB。空闲 <15 GB 时先清理再继续，下载类包暂停并在 `sprint1_progress.md` 报告。
- 时间盒是按这个配额估的；实测比盒子快（预计 xls-r-2b 全量提特征 15–30 分钟）就把省下的时间让给下一个包，不要空等。

## 2. 调度器与"不空转"规则（本冲刺的核心）
- **包表**：`x3/packages.yaml` 记每个包的 `id / 车道(A,B,G,N=网络) / 依赖 / 预计时长 / 优先级 / 资源(线程、显存) / 产物`；`x3/state.json` 记每个包的**实际产物**与状态 `DONE / DONE_ALT / BLOCKED / TIMEOUT / TODO`（恢复逻辑只读它，不按声明的文件名判断）。写一个常驻的小调度循环（tmux 窗口），不要靠人工逐个启动。
- **填空规则（work-conserving）**：任一车道空闲超过 2 分钟，立即从全局就绪队列按优先级取该车道能执行的就绪包；没有就绪包就取该车道**积压队列**（§5）的第一个。**每个车道的积压队列任何时刻都要保有 ≥2 小时的工作量**；不足时从 S5 取并拆小补满。
- **agent 写代码时三条车道也必须在跑**：S1-A（harness）写代码的那一小时里，A 车道跑预取包 P-2、P-3，B 车道跑 P-1、P-4，G 车道跑 G-A1、G-A2、G-B 与 N-1（见 §3）。
- **利用率看门狗**：每 5 分钟追加一行到 `x3/util.csv`（GPU 利用率 / 显存 / 平均负载 / 各车道当前包）。规则：(i) GPU 10 分钟平均利用率 <40% 且没有 G 包在跑 → 立即起下一个 G 包；(ii) G 包在跑但利用率 <40% 超过 10 分钟 → 判断瓶颈（数据加载 / CPU 争用 / IO / 小批量），把 worker 加到 ≤6 或预解码缓存，记录原因并继续；(iii) A+B 的 CPU 使用率 <50% 超过 10 分钟且有就绪的 A/B 包 → 立即起；(iv) 以上都做过仍空转 → 在 `sprint1_progress.md` 写原因。
- **所有决策由脚本做，不等人**：C1 / C2 / C3 只是**汇报点**，agent 不在检查点停下来等 hongyu；M* 由 `mstar.json` 脚本按 09 的选择规则选；唯一等人的是 `FREEZE_OK`（test）与 `SHUTDOWN_OK`（关机）。
- **时间盒规则**：任一包超过自己时间盒的 1.5 倍 → 标 `TIMEOUT`，保留部分结果，调度器立即起下一个。
- **每 30 分钟**追加一行到 `x3/sprint1_progress.md`：已用时 / 各车道当前包 / 刚完成的包 / 下一个包 / 阻塞 / GPU 与 CPU 近 30 分钟平均利用率。
- **H6 之前不得停机或空转**；做完 S4 后继续吃积压队列直到耗尽或 `SHUTDOWN_OK`；耗尽后进入**等待态**（不关机，等 `FREEZE_OK` / `SHUTDOWN_OK` / `NEW_TASKS.md` / `PAUSE`）。冲刺的终报仍按 H9 写，不等积压做完。
- 约定的汇报点：**C1 ≈ H3、C2 ≈ H5.5、C3 ≈ H7.5、终报 ≈ H9**，各写 `x3/CHECKPOINT_n.md`（模板见 §6）。

## 4. 回退梯（触发条件 → 动作 → 标签）
- **F0 任一包 TIMEOUT**：保留部分结果，调度器起下一个；`state.json` 标 `TIMEOUT`，终报列出。
- **F1 GPU 车道故障（OOM / 驱动 / 网络）**：CPU 车道照常；`S2-E` 改在 CPU 上训（K=5，epoch 减半）；`G-*` 顺延或标 `BLOCKED`；不阻塞 G40。
- **F2 H3 时 P1 harness 仍未通过单测**：擂台先在 P2（`strict_draw`、说话人库口径，沿用 U8 代码）上跑 M-A / M-C / M-D / M-F，P1 在 H6 前补上；到 H6 仍不通 → 终报标 `P1_MISSING`，只报 P2。
- **F3 H5.5（C2）没有任何方法过 G40**：在 H5.5–H7 之间做**一轮**补救，不再展开：(a) 组合最好的部件为 `M-AB`（RAP-joint + 库卫生 + 流特征 + E-norm）；(b) 换头（LR → LightGBM → MLP）；(c) 两个骨干特征拼接；(d) 若缓存里有多层特征，加层加权。补救后仍只有堆叠型组合过线 → 标 `SOTA_STACK_ONLY`（技术贡献弱，如实写）。
- **F4 H7 仍不过 G40**：标 `NO_SOTA_VS_STRONGEST`；终报给出各方法相对最强对手的差距排序；**不得自行再加新方法**，由 hongyu 决定下一步（候选：帧级覆盖、声码器配对假样本方向、M-E / M-G 深挖）。
- **F5 G42 显示稳健变体显著好、但宏平均 EER 不过线**：标 `ROBUST_ONLY`（贡献是"对污染与语言不匹配的稳健打分"，SOTA 声明收窄到污染条件下）。
- **F6 编码归一化 / 非后训练特征使增益保留 <50%**：标 `CHANNEL_DOMINATED`；SOTA 追逐照常，但终报必须并列写出，不得用"检测合成"的措辞。
- **F7 ITW 不可得**：`ITW_UNAVAILABLE` + 原因；若网络可用且下载 ≤2h，用 FSW 评测集子集（≤20k 条；标签按账号，账号内强聚类，单独标注）替代；否则跳过，不拖别的。
- **F8 任一 `RECOMPUTE_MISMATCH`**：头条数字暂停引用，先查差异（排序并列处理、阈值插值、掩码），修好再继续。
- **F9 利用率看门狗连续告警（§2）**：优先查数据加载 / 小批量；其次把相邻两个 CPU 小包合并成一个大包；记录到 `sprint1_progress.md`。

## 5. 积压队列（每条车道保有 ≥2h；按优先级取；G 车道积压不得为空）
**G 车道积压**（GPU 能一直做的事）：
1. `X-J1` 帧级覆盖（PatchCore 式，帧特征 PCA-64，≤1.3 GB）；`X-J2` 编解码响应信号；`X-J3` 声码器配对假样本方向（复用 `G-C` 的重合成）——各自先写事前预测与杀死线，时间盒 1h，结果进"信息性"表，不改 M*。
2. `X-F` 另一个骨干（hubert-xlarge 的 AntiDeepfake 权重，若已缓存）上重复头条；`X-L` 骨干拼接特征（xls-r-2b ⊕ mms-1b）上重复头条。
3. `X-M2` M-A 的 MLP / XGBoost-GPU 头在更大超参网格上的敏感性；`X-S2` M-B 的追加种子。
4. `X-G` 库大小曲线延伸到 N=640（同平台 / 他平台，GPU 上批量算距离）。
**CPU 积压**（A、B 通用）：
1. `X-H` **P3 全流程演练**：把 v3 dev 的说话人按平台分层随机二分（源 / 伪目标），用冻结配置从头跑一遍 P3 的全部脚本，保证 `FREEZE_OK` 之后一次就跑通（输出 `p3_rehearsal.csv`，不进主表）。
2. `X-I` **论文用表格与图生成脚本**：从 CSV 一键生成 LaTeX 表（主表、N 曲线、污染曲线、共形操作点、对照表）与图（逐平台森林图、N 曲线、污染曲线、剂量反应），输出 `paper_tables/`、`paper_figs/`。
3. `X-A` 头条配置抽样加到 40 次；`X-B` 逐语言 / 逐平台细分表；`X-K` 超参敏感性（N、k、C、κ 的小网格）与种子方差。
4. `X-C` 微调基线（W13 的 LP-FT / 末块微调）并入 P1；`X-D` PVP 简化版（≤3h 跑不通写原因）；`X-N` 留一语言协议（leave-one-language-out）。
5. `X-E` 标注核查表：按平台×标签分层抽 150 条 clip 的清单（文件路径、元数据、模型分数，不含我们的判断）供 hongyu 人工试听。
